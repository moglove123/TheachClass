# TheachClass — ระบบจัดการชั้นเรียนออนไลน์

แอปพลิเคชันจัดการชั้นเรียนครบวงจร ภาษาไทย 100% รองรับ 3 บทบาท (ผู้ดูแลระบบ / ครู / นักเรียน) ใช้ฐานข้อมูล SQLite จริงผ่าน Prisma ไม่มีข้อมูลจำลอง (mock data) หน้าเว็บเป็น React + Tailwind CSS แบบ Responsive มี Dark Mode ฟอนต์ Noto Serif Thai/Sarabun

ดีไซน์เป็นแนว "ระบบทะเบียน finished โดยสตูดิโอ" มากกว่าการ์ดแดชบอร์ดสำเร็จรูป: พื้นหลัง **ฟ้าอ่อน** (`#f2f7fc`) มีเส้นตารางบาง ๆ แบบสมุดทะเบียน (เส้นเล็ก 28px + เส้นหลัก 140px โทนฟ้า/น้ำเงิน)
เส้นขอบ 1px เป็นตัวแบ่งชั้นแทนเงา, มุมโค้งสั้น, หัวเรื่องใช้ **Noto Serif Thai** เนื้อหาใช้ **Sarabun** และตัวเลขเรียงหลักกัน (tabular) สีหลักคือน้ำเงินทะเลสดใส (`#2d6ba6`) ปรับโทนสีให้มีชีวิตชีวาขึ้นแต่ยังคมชัด เขียว/ส้ม/แดง/ม่วงสงวนให้สถานะและกราฟ ไม่มี gradient, แสงเรือง, glassmorphism หรือการ์ดลอย คลาส `.app-decor` ใน `src/index.css` ใช้กับทุกหน้า
น้ำหนักตัวอักษรหนาขึ้นทั้งระบบ (`normal` → 600, `medium` → 700, `semibold` → 800, `bold` → 900) และขนาดตัวอักษรเพิ่มขึ้นเล็กน้อย (`xs` 13px, `sm` 15px, `base` 17px) เพื่อให้อ่านง่ายบนพื้นฟ้าอ่อน

หน้าเข้าสู่ระบบแบ่งครึ่ง: ฝั่งซ้ายเป็นแผงสีน้ำเงินเข้มเรียบ ๆ มีชื่อระบบ หัวข้อ serif และรายการ features เป็นหมายเลข ฝั่งขวาเป็นฟอร์มบนพื้นฟ้าอ่อน พร้อมป้ายบัญชีทดลองแบบข้อความโมโน ไม่มีภาพประกอบ isometric หรือภาพลอย

ลูกเล่นเหลือเพียง hover เปลี่ยนสี, หน้าใหม่ fade-up เล็กน้อย และ Modal ปรากฏแบบ pop-in สั้น ๆ (ยังเคารพ `prefers-reduced-motion`) — ปุ่มไม่เด้ง ไม่ลอย และไม่สว่างจ้าตอนกด

## 1. สิ่งที่ระบบทำได้

### นักเรียน (STUDENT)
- สมัครสมาชิก / เข้าสู่ระบบ / ลืมรหัสผ่าน / เปลี่ยนรหัสผ่าน / ออกจากระบบ
- เข้าร่วมห้องเรียนด้วย **รหัสเข้าห้องเรียน (Join Code)** หรือครูเพิ่มรายชื่อให้
- **เช็กชื่อด้วยตำแหน่งปัจจุบัน (GPS จริง)** เฉพาะใน **รอบที่ครูเปิดเมื่อต้องการ** (ไม่ได้เปิดตลอดเทอม)
  - ครูเป็นฝ่ายกด “เปิดรอบเช็กชื่อ” ระบบจะอ่านพิกัดปัจจุบันของครูเป็นจุดอ้างอิงของรอบนั้น และแจ้งเตือนนักเรียนทันที
  - ระบบตรวจระยะทางฝั่งเซิร์ฟเวอร์ด้วยสูตร Haversine (ไม่เชื่อค่าระยะทางที่เบราว์เซอร์ส่งมา)
  - ป้องกันเช็กชื่อซ้ำในวันเดียวกัน, ตรวจช่วงเวลาเปิด–ปิดของรอบ, ตรวจความสาย
  - แจ้งเตือนความผิดปกติเบื้องต้น เช่น ความคลาดเคลื่อน GPS สูง / ความเร็วการเดินทางผิดปกติ
  - > **หมายเหตุสำคัญ:** ระบบตรวจจับเบื้องต้น **ไม่สามารถยืนยันการปลอม GPS ได้ 100%** (ข้อมูลตำแหน่งส่งมาจากอุปกรณ์ของผู้ใช้เสมอ)
  - มีช่องยืนยันความยินยอมเก็บตำแหน่ง (GPS consent) ก่อนกดเช็กชื่อ
- เห็น **“งานที่ขาดส่ง”** โดยระบบรวมงานที่กำหนดส่งผ่านแล้วแต่ยังไม่ส่ง แยกตามวิชา พร้อมจำนวนวันที่เกินกำหนด
- ส่ง **คำร้องแจ้งลา** ให้ครูของวิชานั้นพิจารณา (ระบุวันที่และเหตุผล) ยกเลิกคำร้องที่ยังรอตรวจได้ และรับการแจ้งเตือนผลการพิจารณา
- ดูตารางงาน คำนวณเวลาเหลือ (countdown) ส่งงานพร้อมแนบไฟล์ ส่งซ้ำได้ (attempt) ดูคะแนนและประวัติการแก้คะแนน
- ดูคะแนนและเกรดของ **ตัวเองเท่านั้น** (คำนวณอัตโนมัติจากน้ำหนักคะแนนและเกณฑ์ตัดเกรด)
- ดูประวัติการเข้าเรียน ประกาศ และการแจ้งเตือน (นับจำนวนที่ยังไม่ได้อ่าน)

### ครู (TEACHER)
- สร้าง / แก้ไข / ลบห้องเรียน แยกตามวิชา ภาคเรียน ปีการศึกษา กำหนดรหัสเข้าห้องเรียน น้ำหนักคะแนน และเกณฑ์ตัดเกรด
- **เปิด/ปิดรอบเช็กชื่อเมื่อต้องการ** โดยระบบใช้ตำแหน่งปัจจุบันของครูเป็นพิกัดอ้างอิง (กำหนดรัศมี ระยะเวลาเปิดรอบ และเวลาที่ถือว่ามาสายได้)
- เพิ่ม/นำนักเรียนออกจากห้องเรียน ดูรายชื่อ สรุปการเข้าเรียน และแก้ไขสถานะ (PRESENT/LATE/ABSENT/LEAVE) พร้อม **ประวัติการเปลี่ยนแปลงทุกครั้ง**
- แท็บ **“สมาชิก”** แสดง **ชื่อ–นามสกุลและรูปโปรไฟล์ของนักเรียนทุกคน** (ถ้าไม่ได้อัปโหลดรูปจะแสดงตัวอักษรย่อแทน) คู่กับรหัสนักเรียน อีเมล สถิติเข้าเรียนและส่งงาน
- รับคำร้องลาของนักเรียน อนุมัติ/ปฏิเสธได้ เมื่ออนุมัติระบบจะบันทึกสถานะ `LEAVE` ให้และแจ้งเตือนนักเรียนอัตโนมัติ
- สร้าง/แก้ไข/ปิด-เปิด/ลบงาน กำหนดกำหนดส่ง คะแนนเต็ม คะแนนพิเศษ รับส่งช้า หักคะแนนส่งช้า และต่อเวลา
- ตรวจงาน ให้คะแนน แก้คะแนน พร้อม **Score Log** และสถิติการส่งงานของห้อง
- บันทึกคะแนนเก็บ / กลางภาค / ปลายภาค / กิจกรรม / คะแนนพิเศษ พร้อม Grade Log
- เผยแพร่ประกาศ ส่งออก Excel ตามห้องเรียน/วิชา/ภาคเรียน/ปีการศึกษา
- กด **“สรุปคะแนนทั้งหมด → Excel”** ในหน้าคะแนน (หรือการ์ด “สรุปคะแนนนักเรียนทุกคน” ในหน้ารายงาน) เพื่อโหลดไฟล์คะแนนของทุกคนในชั้นเรียนที่เลือก **โดยไฟล์จะตั้งชื่อตามชื่อชั้นเรียน** เช่น `ม.5_1_วิทยาการคอมพิวเตอร์_สรุปคะแนน.xlsx`

### ผู้ดูแลระบบ (ADMIN)
- ระงับ / เปิดใช้งานอีกครั้ง / แก้ไข / ลบบัญชี และ **มอบอำนาจ (เปลี่ยน Role) ได้จากตารางผู้ใช้หรือแบบหลายบัญชี** (บัญชีสมัครใหม่เป็น `ACTIVE` อยู่แล้ว จึงไม่ต้องอนุมัติซ้ำ)
  - เลือก `ผู้ดูแลระบบ / ครู / นักเรียน` แล้วระบบจะแจ้งเตือนผู้ใช้, บันทึก Audit Log (`CHANGE_ROLE` / `BULK_UPDATE_USER`) และให้ค้นย้อนหลังได้ในหน้าประวัติการแก้ไข
  - มีการกันไม่ให้เปลี่ยนสิทธิ์/สถานะบัญชีของตัวเอง และกันไม่ให้ระบบไม่มีผู้ดูแลที่เปิดใช้งานเหลืออยู่
- ดูสถิติภาพรวม, การใช้งาน, บันทึก Audit Log ทั้งหมด (กรองตามการกระทำได้)
- ตั้งค่าระบบ เช่น รัศมี GPS เริ่มต้น, นาทีที่ถือว่าสาย, **ช่วงเวลาแจ้งเตือนก่อนกำหนดส่ง (เช่น 24,12,1 ชั่วโมง)**, ปีการศึกษา/ภาคเรียน
- สำรองข้อมูลทั้งระบบเป็นไฟล์ JSON (`GET /api/admin/backup`) **ไม่รวมรหัสผ่าน**
- เข้าถึงรายงาน Excel ของทุกห้องเรียน
- เห็นรูปโปรไฟล์ของสมาชิกทุกคนในตารางผู้ใช้ และลบรูปของบัญชีอื่นได้ (`DELETE /api/users/:id/avatar`)

### ทุกสิทธิ์ (นักเรียน / ครู / ผู้ดูแล) — โปรไฟล์และรูปโปรไฟล์
- เมนู **“โปรไฟล์ของฉัน”** มีให้ครบทั้ง 3 สิทธิ์ (ด้านล่างของเมนูหลัก + รูปที่มุมขวาบน + การ์ดชื่อในแถบข้าง)
- อัปโหลด / เปลี่ยน / ลบ **รูปโปรไฟล์จริง** ได้จากหน้าโปรไฟล์ (เลือกไฟล์ → ดูตัวอย่าง → กดบันทึก)
  - รองรับ `PNG / JPG / GIF / WEBP` ขนาดไม่เกิน **5 MB**
  - ตรวจ **Signature ของไฟล์จริง** ฝั่งเซิร์ฟเวอร์ ป้องกันการเอาไฟล์อื่นมาเปลี่ยนชื่อเป็น `.png`
  - เก็บใน `uploads/avatars/` และลบไฟล์เก่าอัตโนมัติเมื่อเปลี่ยน/ลบรูป
  - บันทึก Audit Log `UPLOAD_AVATAR` / `DELETE_AVATAR` ทุกครั้ง
- แก้ไขชื่อ นามสกุล และเบอร์โทรของตัวเองได้ (`PATCH /api/profile`) โดยอีเมล/รหัสนักเรียน/สิทธิ์ยังคงเป็นของผู้ดูแลจัดการตามเดิม
- ถ้าโหลดรูปไม่ได้ (ลบไฟล์จากดิสก์) หน้าเว็บจะถอยกลับไปแสดง **ตัวอักษรย่อ** อัตโนมัติ ไม่ให้หน้าเพี้ยน

**Endpoint ที่เกี่ยวข้อง**

| Endpoint | สิทธิ์ | รายละเอียด |
| --- | --- | --- |
| `GET /api/profile` | ทุกสิทธิ์ | ใช้ `/api/auth/me` แทน (มี `avatarUrl` อยู่แล้ว) |
| `PATCH /api/profile` | ทุกสิทธิ์ | แก้ `firstName`, `lastName`, `phone` ของตัวเอง |
| `POST /api/profile/avatar` | ทุกสิทธิ์ | multipart field ชื่อ `avatar` → คืนข้อมูลผู้ใช้ที่มี `avatarUrl` ใหม่ |
| `DELETE /api/profile/avatar` | ทุกสิทธิ์ | ลบรูปของตัวเอง |
| `GET /api/profile/avatar/:filename` | ผู้ล็อกอินทุกคน | เสิร์ฟรูป (ตรวจว่ามีผู้ใช้อ้างอิงอยู่จริงกันการอ่านไฟล์มั่ว) |
| `DELETE /api/users/:id/avatar` | เฉพาะ ADMIN | ลบรูปของบัญชีอื่น |

## 3. ติดตั้งและรัน (Development)

### ความต้องการ
- Node.js 20 ขึ้นไป (แนะนำ 26) และ npm 11
- ไม่ต้องติดตั้ง PostgreSQL/MySQL เพราะใช้ SQLite

### ขั้นตอน

```powershell
# 1) เข้าไปยังโฟลเดอร์โปรเจกต์
cd "C:\Users\yoemm\OneDrive\Desktop\test class"

# 2) ติดตั้งแพ็กเกจ
npm install

# 3) อนุญาตสคริปต์ของ Prisma/esbuild (จำเป็นสำหรับ npm 11 ที่บล็อกสคริปต์อัตโนมัติ)
npm install-scripts approve @prisma/client @prisma/engines esbuild prisma

# 4) สร้าง Prisma Client
npm run prisma:generate

# 5) สร้างตาราง + ใส่ข้อมูลเริ่มต้น (seed)
npm run db:setup

# 6) รันพร้อมกันทั้ง API (4000) และเว็บ (5173)
npm run dev
```

เปิดเบราว์เซอร์ที่ **http://localhost:5173**

> ถ้า `npm install-scripts approve ...` พบแพ็กเกจที่ยังไม่ได้รับการอนุมัติ ให้รันคำสั่งที่ npm แนะนำเพิ่มเติม แล้วรัน `npm run prisma:generate` อีกครั้ง

### บัญชีเริ่มต้น

สร้างผู้ดูแลระบบด้วยการตั้งค่าฐานข้อมูลหรือเพิ่มบัญชีผ่านระบบตามนโยบายของสถานศึกษา ระบบไม่มีบัญชีทดลองใช้งานแสดงในหน้าเข้าสู่ระบบ

## 4. Production build

```powershell
npm run build     # สร้าง dist/
npm start         # Express เสิร์ฟ dist/ + API ที่ http://localhost:4000
```

Express จะทำ SPA fallback: ทุก GET ที่ไม่ใช่ `/api/*` จะส่ง `dist/index.html`

## 5. ตัวแปรสภาพแวดล้อม (`.env`)

คัดลอกจาก `.env.example` แล้วปรับค่า:

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
| --- | --- | --- |
| `DATABASE_URL` | Connection string ของ PostgreSQL ที่โฮสต์จริง | `postgres://USER:PASSWORD@pooled.db.prisma.io:5432/postgres?sslmode=require&connect_timeout=15` |
| `JWT_SECRET` | กุญแจเซ็น token **ต้องเปลี่ยนใน production** | — |
| `PORT` | พอร์ต API | `4000` |
| `UPLOAD_DIR` | โฟลเดอร์เก็บไฟล์ | `./uploads` |
| `MAX_FILE_SIZE_MB` | ขนาดไฟล์อัปโหลดสูงสุด | `20` |

ใน production ควรตั้ง `NODE_ENV=production` เพื่อให้ cookie เป็น `secure` (ต้องใช้ HTTPS) และควรเดา JWT_SECRET ที่ยาวและไม่ซ้ำใคร

### Deploy บน Vercel (Serverless)

`vercel.json` ส่ง `/api/*` ไป `@vercel/node` (`server/index.js`) และส่งคำขออื่นไป `dist` พร้อม SPA fallback จึงไม่ต้องตั้ง Vite proxy บน Vercel

ตัวแปรที่ต้องตั้งใน **Vercel → Project → Settings → Environment Variables**:

| ตัวแปร | ความหมาย | หมายเหตุ |
| --- | --- | --- |
| `DATABASE_URL` | Connection string ของฐานข้อมูลที่โฮสต์จริง | **SQLite ไม่ใช้ได้บน Vercel** — `schema.prisma` ใช้ `provider = "postgresql"` (Prisma Postgres/Neon/Supabase) |
| `DIRECT_URL` | Connection string สำหรับ migration | เฉพาะกรณีใช้ PgBouncer แล้วเปิด `directUrl` ใน schema |
| `JWT_SECRET` | กุญแจเซ็น token | สุ่ม ≥ 24 ตัว production จะบล็อกค่าตัวอย่าง |
| `APP_BASE_URL` | Domain จริงของเว็บ | ใช้ประกอบลิงก์ reset password |
| `EMAIL_API_URL` / `EMAIL_API_KEY` | Email gateway | จำเป็นสำหรับ “ลืมรหัสผ่าน” ใน production |
| `MAX_FILE_SIZE_MB` | ขนาดไฟล์อัปโหลดสูงสุด | ไม่บังคับ (ค่าเริ่มต้น 20) |

ก่อน deploy ให้รัน `npx prisma db push` โดยตั้ง `DATABASE_URL` ชี้ไปฐานข้อมูลจริง (แนะนำ host แบบ direct `db.prisma.io` สำหรับคำสั่ง CLI) เพื่อสร้างตาราง แล้วจึงกด Deploy

> `schema.prisma` ใช้ PostgreSQL เพียงตัวเดียว ส่วน `npm test` ใช้ `prisma/schema.test.prisma` (SQLite) แยกต่างหาก จึงไม่ต้องสลับ schema เอง

> ไฟล์ที่อัปโหลดบน Vercel เก็บใน `/tmp` (เขียนได้แต่ไม่ถาวร) ถ้าต้องการเก็บไฟล์จริงระยะยาว ต้องเปลี่ยนจาก disk เป็น object storage เช่น Vercel Blob/S3

## 7. รายงาน Excel (ส่งออกทีละห้องหรือหลายห้อง)

| Endpoint | ชีตที่ได้ |
| --- | --- |
| `GET /api/exports/options` | ตัวกรองตามสิทธิ์ (ครู `OWN` เฉพาะวิชาที่สอน / ผู้ดูแล `ALL` ทุกวิชา) |
| `GET /api/exports/full` | **6 ชีต**: ข้อมูลนักเรียน, สรุปการเข้าเรียน, คะแนนงาน, คะแนนสอบ, สรุปผลการเรียน, สรุปภาพรวม |
| `GET /api/exports/attendance` | ข้อมูลนักเรียน + สรุปการเข้าเรียน + สรุปภาพรวม |
| `GET /api/exports/grades` | ข้อมูลนักเรียน + คะแนนสอบ + สรุปผลการเรียน + สรุปภาพรวม |
| `GET /api/exports/grading` | ข้อมูลนักเรียน + คะแนนงาน + สรุปผลการเรียน + สรุปภาพรวม |
| `GET /api/exports/student-scores?classroomId=...` | **สรุปคะแนนทั้งหมดของทุกคนใน 1 ชั้นเรียน** (ชีต “สรุปคะแนนทั้งหมด” รวมคะแนนงานแต่ละรายการ, คะแนนเก็บ/สอบ/กิจกรรม, คะแนนรวม, เกรด, ผลการเรียน, จำนวนงานส่ง/ขาดส่ง) + ชีตเดิม 5 ชีต **ชื่อไฟล์ = ชื่อชั้นเรียน** |

- **ครูส่งออกได้เฉพาะวิชาที่ตนสอน:** `GET /api/exports/options` คืน `scope: 'OWN'` พร้อมรายวิชา/ห้อง/ภาคเรียน/ปีการศึกษาของครูคนนั้น (ผู้ดูแลได้ `scope: 'ALL'` และทุกวิชา) หน้ารายงานใช้ endpoint นี้เป็นแหล่งเดียวของตัวกรอง และฝั่งเซิร์ฟเวอร์ยังตรวจอีกชั้น — ครูที่ส่ง `subjectCode` ของครูคนอื่นมาจะได้ 404

**ตัวกรอง (query string):** `classroomId`, `semester`, `academicYear`, `subjectCode` (สำหรับ `student-scores` ต้องระบุ `classroomId`)
ตัวอย่าง: `/api/exports/full?classroomId=1&semester=1&academicYear=2026`

- **สมัครได้เฉพาะบัญชีนักเรียน และใช้งานได้ทันที:** หน้าสมัครไม่มีตัวเลือก “ครู” และ API `POST /api/auth/register` บังคับ `role: 'STUDENT'` + `status: 'ACTIVE'` เสมอ แม้ส่ง `role: 'TEACHER'` มาก็ตาม — การเป็นครู/ผู้ดูแลต้องให้ผู้ดูแลระบบมอบสิทธิ์ในหน้า “ผู้ใช้” เท่านั้น (ปุ่มยืนยันเป็นสีฟ้า ไม่ใช่ปุ่มลบสีแดง)
- **แยกเจ้าของห้องเรียน:** ครูที่สร้างห้องจะเป็นเจ้าของ (`teacherId`) เห็นเฉพาะห้องของตัวเองทุกหน้า (ห้องเรียน, แดชบอร์ด, งาน, เช็กชื่อ, คะแนน, รายงาน, คำร้องลา, ไฟล์แนบ) ครูคนอื่นเรียกตรง ๆ จะได้ 403/404 และแก้ไขไม่ได้
- ผู้ดูแลสร้างห้องได้แล้ว **เลือกครูผู้สอนเป็นเจ้าของห้อง** และเห็น/จัดการทุกห้องได้ (การโอนห้องต้องระบุเป็นบัญชีครูเท่านั้น)
- ครูเห็นเฉพาะห้องของตัวเอง (พยายามเรียกห้องของครูคนอื่นจะได้ 404)
- ผู้ดูแลเห็นทุกห้อง
- นักเรียนไม่มีสิทธิ์ส่งออก (403)
- ไฟล์ที่ได้เป็น **.xlsx จริง** (ExcelJS เขียนเป็น ZIP/OpenXML) เปิดด้วย Microsoft Excel / Google Sheets / LibreOffice ได้ทันที
- ชื่อไฟล์ภาษาไทยส่งผ่าน `filename*=UTF-8''...` ตาม RFC 5987 และฝั่งหน้าเว็บตั้งชื่อผ่าน `a.download` จากชื่อชั้นเรียนโดยตรง (มีชื่อ ASCII สำรองเผื่อเบราว์เซอร์เก่า)
- ข้อความในไฟล์ใช้ฟอนต์ **Tahoma** เพื่อให้ภาษาไทยแสดงผลถูกต้องบน Excel/Windows แม้ไม่ได้ติดตั้งฟอนต์ที่ใช้บนเว็บ
- ในชีต "สรุปผลการเรียน" มีฟอร์มูล่าคำนวณเกรดและสถานะ **ผ่าน / ไม่ผ่าน** และใน "สรุปภาพรวม" มีฟอร์มูล่า AVERAGE/COUNTIF
- ทุกการส่งออกถูกบันทึกใน Audit Log (`EXPORT_EXCEL`)

## 8.1 การเช็กชื่อเป็นรอบ / แจ้งลา / งานที่ขาดส่ง

### เช็กชื่อเป็นรอบ (ไม่เปิดตลอดเทอม)
1. ครูเข้า **หน้าเช็กชื่อ** เลือกห้องเรียน แล้วยืนยันความยินยอมใช้ตำแหน่งปัจจุบัน
2. กด **“เปิดรอบเช็กชื่อ”** เบราว์เซอร์จะอ่านพิกัดปัจจุบันของครู แล้วระบบบันทึกเป็นพิกัดอ้างอิงของรอบนั้น (พร้อมรัศมีและเวลาปิดรอบ)
3. นักเรียนในห้องได้รับการแจ้งเตือน `CHECKIN_OPEN` และกด **“เช็กชื่อตอนนี้ (ใช้พิกัดปัจจุบัน)”** ได้เฉพาะขณะรอบเปิดอยู่
4. ครูกด **“ปิดรอบ”** ได้ทุกเมื่อ ระบบจะแจ้ง `CHECKIN_CLOSED` และไม่อนุญาตให้เช็กชื่อในรอบนั้นอีก

API ที่เกี่ยวข้อง:
- `POST /api/attendance/sessions` — เปิดรอบ (ส่ง `classroomId`, `lat`, `lng`, `accuracy`, `gpsRadius?`, `durationMinutes?`)
- `GET /api/attendance/sessions/active` — รอบที่เปิดอยู่ตามสิทธิ์ของผู้ใช้
- `GET /api/attendance/sessions?classroomId=...` — ประวัติรอบของครู
- `POST /api/attendance/sessions/:id/close` — ปิดรอบ
- `POST /api/attendance/checkin` — ยังใช้เส้นทางเดิมได้ แต่ต้องมีรอบเปิดอยู่ (หรือข้อมูลเดิม `attendanceOpen` ที่เปิดไว้ก่อนการอัปเดต)

> ข้อมูลเก่าที่ตั้งค่า `attendanceOpen: true` ไว้ยังเช็กชื่อได้เพื่อความเข้ากันได้ แต่หน้าต่างการตั้งค่าไม่ได้เปิดให้สร้างการเช็กชื่อแบบตลอดเทอมอีกต่อไป

### ระบบแจ้งลา
- นักเรียน: `POST /api/leaves` (`classroomId`, `date?`, `reason`), `GET /api/leaves`, `DELETE /api/leaves/:id` (ยกเลิกเฉพาะคำร้องที่ยัง `PENDING`)
- ครู: `GET /api/leaves?classroomId=...`, `PATCH /api/leaves/:id/review` (`status: APPROVED | REJECTED`, `reviewNote?`)
- เมื่ออนุมัติ ระบบสร้าง/อัปเดต `Attendance` เป็น `LEAVE`, บันทึก `AttendanceLog`, Audit Log และแจ้งเตือนนักเรียน (`LEAVE_APPROVED`)
- ครูเห็นจำนวนคำร้องรอตรวจได้ในหน้าแรก และจัดการได้ในหน้าเช็กชื่อ

### งานที่ขาดส่ง
- `GET /api/assignments/missed` หรือ `GET /api/submissions/missed` (เฉพาะ `STUDENT`) คืนงานที่กำหนดส่งผ่านแล้วและยังไม่มี Submission ของนักเรียนคนนั้น
- ข้อมูลนี้ถูกคำนวณจากห้องที่นักเรียนลงทะเบียนเท่านั้น จึงไม่เปิดเผยงานหรือคะแนนของผู้อื่น
- แสดงเป็นการ์ดเตือนในหน้าแรก หน้างาน และกรองได้ด้วย `?status=missed`
- `GET /api/assignments` ของนักเรียนแนบ `mySubmission` (ความพยายามล่าสุด: `status`, `isLate`, `attempt`, `submittedAt`, `score`) มาด้วย → หน้ารายการงานแสดงป้าย **ส่งแล้ว / ส่งช้า / ตรวจแล้ว / ยังไม่ส่ง / ขาดส่ง** บนการ์ดเลย ไม่ต้องกดเข้าไปดูในงาน และกรองได้ด้วย `?status=sent|pending|late|graded|missed`

### การมอบอำนาจ / จัดการผู้ใช้โดยผู้ดูแล
- `PATCH /api/users/:id` ส่ง `{ role: 'ADMIN' | 'TEACHER' | 'STUDENT' }` เพื่อเปลี่ยนสิทธิ์รายคน (หรือ `{ status }` เพื่ออนุมัติ/ระงับ)
- `POST /api/users/bulk` ส่ง `{ ids: [1,2,3], role: 'TEACHER' }` หรือ `{ ids: [...], status: 'ACTIVE' | 'SUSPENDED' }` เพื่อมอบสิทธิ์/เปลี่ยนสถานะหลายบัญชี (สูงสุด 100 บัญชี)
- ทุกการเปลี่ยนสิทธิ์จะแจ้งเตือนผู้ใช้ (`ROLE_CHANGED`) และบันทึก Audit `CHANGE_ROLE` / `BULK_UPDATE_USER`
- `GET /api/admin/audit-logs?action=CHANGE_ROLE` กรองประวัติตามการกระทำได้ (หน้าประวัติการแก้ไขมีตัวเลือกกรองแล้ว)
- ข้อจำกัดด้านความปลอดภัย: เปลี่ยนสิทธิ์/สถานะบัญชีตัวเองไม่ได้, ต้องมี ADMIN ที่ `ACTIVE` อย่างน้อย 1 บัญชี, บัญชีที่ถูกข้ามจะแจ้งในผลลัพธ์ `skipped`

## 9. ความปลอดภัย

- รหัสผ่านแฮชด้วย bcrypt เก็บใน DB (ไม่มีการส่งรหัสผ่านไปยัง frontend หรือไฟล์ Backup)
- JWT เก็บใน **httpOnly cookie** (SameSite=Lax) ตรวจสิทธิ์ทุก Request และเช็คสถานะบัญชีทุกครั้ง
- Admin เท่านั้นที่ใช้ `/api/users` และ `/api/admin/*`; ครูจัดการได้เฉพาะห้องของตัวเอง; นักเรียนเห็นเฉพาะข้อมูลของตัวเอง
- นักเรียนไม่สามารถดูตารางเช็กชื่อของนักเรียนคนอื่น หรือดาวน์โหลดไฟล์ส่งงานของคนอื่นได้
- ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ด้วย `assertClassroomAccess()` ทุกเส้นทางที่แตะข้อมูลห้องเรียน
- ตรวจประเภท ขนาด **และ magic byte ของไฟล์จริง** (PDF, Word, Excel, รูปภาพ, ZIP, PPT, TXT/CSV / สูงสุด 20MB) กันการ rename ไฟล์อื่นเป็น `.png`/`.pdf`
- ดาวน์โหลดไฟล์ผ่าน `/api/files/:filename` เท่านั้นและต้องผ่านการตรวจสิทธิ์ (ครูได้เฉพาะไฟล์ในห้องที่ตนสอน) บังคับ `Content-Disposition: attachment` + `nosniff`
- Production บล็อก startup ทันทีถ้า `JWT_SECRET` เป็นค่าตัวอย่าง/สั้นเกิน 24 ตัว (ดู `.env.example`) และบังคับรหัสผ่านอย่างน้อย 8 ตัว
- Security headers ทุก response: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` (+ CSP แบบเต็มเฉพาะ production)
- เปลี่ยนรหัสผ่าน / สิทธิ์ / สถานะบัญชีโดย ADMIN → เพิ่ม `tokenVersion` → token เก่าของบัญชีนั้นใช้ไม่ได้ทุกเครื่องทันที
- ทุก query ที่ระบุ `classroomId` (เช่น `/api/leaves?classroomId=...`) จะตรวจ `assertClassroomAccess()` ก่อน ไม่ให้ค่าที่ส่งมาไปทับเงื่อนไขจำกัดห้องของครู
- บันทึก Audit Log สำหรับการเข้าสู่ระบบ, การแก้ไข, การให้คะแนน, การลบ, การสำรองข้อมูล ฯลฯ
- ลบผู้ใช้จะปฏิเสธถ้ายังเป็นครูที่ดูแลห้องเรียนอยู่ (ต้องโอนห้องก่อน)

### ลืมรหัสผ่าน
- **โหมดพัฒนา/สาธิต (`NODE_ENV` ไม่ใช่ `production`)**: เนื่องจากยังไม่ได้ configuration บริการอีเมล `POST /api/auth/forgot-password` จะ **ส่ง reset token กลับมาใน response โดยตรง** (ใช้งานได้ 1 ชั่วโมง) แล้วนำ token ไปเรียก `POST /api/auth/reset-password` พร้อม `newPassword`
- **Production**: ต้องตั้ง `EMAIL_API_URL` (และ `EMAIL_API_KEY` ถ้าบริการต้องการ) ระบบจะ POST JSON `{ to, subject, text, token, resetUrl }` ไปยัง gateway ดังกล่าว **ไม่คืน token ใน response** และตอบข้อความรวม ๆ ทุกกรณีเพื่อป้องกันการเดาอีเมลในระบบ ถ้าไม่ได้ตั้งค่าบริการอีเมลจะตอบ `503` แทน
- หลังเปลี่ยนรหัสผ่านสำเร็จ ระบบจะเพิ่ม `tokenVersion` ของผู้ใช้ → **บังคับออกจากทุกอุปกรณ์ทันที** ต้องล็อกอินใหม่
- Rate limit: login 20 ครั้ง/15 นาที, register 20 ครั้ง/ชม., forgot/reset 10 ครั้ง/ชม. ต่อ IP (ปิดอัตโนมัติตอน `NODE_ENV=test`)

### สำรอง / กู้คืน / Migration
- สำรอง: `GET /api/admin/backup` (หรือ `POST`) → ไฟล์ JSON `theachclass-backup-<timestamp>.json` ไม่รวม `passwordHash`
- กู้คืน (ข้อมูลใน `DATABASE_URL` **จะถูกแทนที่ทั้งหมด**):
  ```powershell
  npm run db:restore -- .\theachclass-backup-....json --force
  ```
  หลังกู้คืนผู้ใช้ทุกคนต้องขอเปลี่ยนรหัสผ่านใหม่ (ระบบสุ่ม hash ให้ชั่วคราว) และมี Audit `RESTORE_BACKUP`
- ก่อนเปลี่ยน `prisma/schema.prisma` ในจริง: รัน `prisma migrate dev --name <ชื่อ>` เสมอ (โปรเจกต์ใช้ `db push` สำหรับ dev/test) แล้วสำรอง DB ก่อนเสมอ
- แนะนำเปิด SQLite WAL สำหรับทีมเล็ก หรือย้าย PostgreSQL ถ้าใช้งานพร้อมกันหลายโปรเซส

## 12. ข้อจำกัดที่ควรทราบ

- **GPS ไม่สามารถกันการปลอมตำแหน่งได้ 100%** ระบบตรวจเฉพาะระยะทาง ความคลาดเคลื่อน และความเร็วการเดินทางแบบเบื้องต้น
- การแจ้งเตือนจัดเก็บในระบบ (in-app) ยังไม่มีอีเมล/SMS/Push จริง
- รายงาน Excel ใช้ฟอนต์ **Tahoma** เพื่อให้ภาษาไทยแสดงผลถูกต้องบน Windows Excel หากเครื่องเปิดไม่มีฟอนต์ จะสลับไปฟอนต์อัตโนมัติ
- ฐานข้อมูล SQLite เหมาะกับการใช้งานในเครื่อง/ทีมขนาดเล็ก ถ้าต้องการ production ขนาดใหญ่แนะนำย้ายไป PostgreSQL โดยแก้ `datasource` ใน `schema.prisma`
- Rate limit เก็บใน memory ต่อโปรเซส เหมาะกับ deployments แบบ single instance; ถ้า scale หลาย instance ให้ใช้ Redis/shared store
- Production ควรเปิด HTTPS เสมอ (`secure` cookie จะถูกส่งเฉพาะบน HTTPS) และตั้ง `APP_BASE_URL` ให้ตรงกับโดเมนจริง
- ยังไม่มีบริการอีเมล/SMS/Push ในตัว — production ต้องต่อ `EMAIL_API_URL` เอง (ดูหัวข้อลืมรหัสผ่าน)
